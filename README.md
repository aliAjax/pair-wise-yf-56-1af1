# pair-wise-yf-56 网络安全事件响应作战室

## 源提示词摘要
值班人员接收告警，分析人员补充资产和影响范围，响应负责人批准隔离、封禁或恢复动作，法务和公关维护对外口径。系统展示实时事件时间线、子事件、审批、证据和责任人；高优先级动作双人确认，敏感内容按角色显示，并支持只读演示模式。

## 技术栈
Next.js 15 + TypeScript + App Router + shadcn/ui 本地组件 + Zustand + TanStack Query + React Hook Form + Zod + next-intl + date-fns + dnd-kit。

## 已实现闭环
- 主事件、子事件、处置动作和实时时间线。
- 子事件创建、动作审批、双人确认和执行状态流转。
- 角色权限控制、敏感内容遮蔽、只读演示模式。
- dnd-kit 调整处置优先级、TanStack Query 实时连接检查和 Zustand 持久化。

## 对外通报修订与会签流程
主事件、对外通报、审批记录、事件时间线已接成一条修订链：

- **版本化通报**：法务与公关各自维护对外口径，每次保存（标题/段落）即生成新版本；通报含公开段落与敏感段落（技术细节 IOC、法律口径）。
- **事件驱动失效**：出现新证据、影响范围扩大（新增受影响资产）或处置状态变化时，`version+1`、当前生效批准全部标记 `invalidated`（记录保留并注明原因），通报退回待审，时间线留痕。
- **双角色会签**：响应负责人 + 法务按**角色去重**，同一角色重复确认只算一次；两人齐批才进入「已批准·待发布」。
- **乐观锁**：会签携带“所看版本号”。两个角色几乎同时提交、后到一方所看版本已过期时，会被拒绝并提示最新版本与更新人，同步后才能确认。
- **失败保留 + 幂等重试**：发布锁定“待重试内容 + 审批现场”快照；模拟首发失败后状态为「失败·待重试」，事件再变化只让版本继续演进、发布单不动；重试沿用同一发布单号、只累加尝试次数，只生成一条发布结果，且按锁定版本的会签内容发布。
- **敏感段落按角色显示**：分析员/访客只见公开段落，响应负责人/法务/公关可见敏感段落；发布快照中的敏感段落同样按当前角色遮蔽。
- 角色：分析员、响应负责人、法务、公关、访客；只读演示模式冻结全部修订/会签/发布操作。

逻辑测试：`npm test`（node:test，覆盖失效链、会签去重、乐观锁冲突、幂等重试、角色遮蔽、演示冻结）。
